# Nexora Care Triage Prioritization

**Experimental output. Not a clinical decision.**

Nexora Care's first-come-first-served telemedicine queue can leave an urgent request
behind an earlier routine request. This project investigates whether intake data
can help estimate recorded urgency and support human review. It combines data
preparation, exploratory analysis, statistical tests, model experiments and a
Streamlit dashboard. It does not diagnose, prescribe, autonomously triage or connect
to a live queue. No reduction in waiting time or improvement in patient outcomes has
been demonstrated.

This file and the [project report](docs/project_report.md) are generated by
[`src/reporting.py`](src/reporting.py) from [prose templates](docs/templates/)
and saved artifacts. Do not edit generated metrics by hand. The
[documentation facts manifest](artifacts/documentation_facts.json) records source
hashes, template hashes and the rendered values. The [Original case-study DOCX](docs/Triage%20Prioritization%20for%20Nexora%20Care%20One%20week%20Free%20Internship%20case%20study.docx) supplies the
requirements, not empirical findings.

## Run locally

Run from the repository root using a Python environment compatible with the pinned
[requirements](requirements.txt):

```sh
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run dashboard/app.py
```

On macOS, XGBoost and LightGBM also require the OpenMP runtime (`brew install libomp`).
Raw source files belong in `data/raw/` and are ignored by Git. Saved Joblib binaries
are also ignored: obtain the compatible trusted model bundle to use the live demo.
The analysis pages use prepared data and artifacts; missing resources show guidance.

```sh
ruff check .
pytest -q
python -m src.validate_artifacts
python -m src.reporting
python -m src.reporting --check
```

To refresh the requirements snapshot after replacing the case-study DOCX, run
`python -m src.reporting --extract-case-study` before regenerating the documentation.
Normal documentation generation reads numerical inputs only from `artifacts/` and
never trains a model, accesses raw patient rows or reevaluates the test set.

## Data and preparation

The actual intake file has **15,085 rows and 23 columns**, with
**9,912 unique patients**. Assessments have **14,809 rows and
8 columns**. The request-key inner join yields **14,809
labelled rows**, **50 prepared columns** and **44
model inputs**; **276 intake requests have no assessment** and are
reported separately. Source: [profile](artifacts/data_profile.json).

| Urgency | Labelled requests | Share |
| --- | --- | --- |
| Low | 5,210 | 35.2% |
| Moderate | 4,813 | 32.5% |
| High | 3,427 | 23.1% |
| Critical | 1,359 | 9.2% |

Actual files differ from the case-study sketch: derive age from birth date at request
time, and retain the already-separated systolic/diastolic fields. Parse timestamps
explicitly; check duplicates, invalid dates, spelling, whitespace and vital bounds.
Duration magnitudes suggest seconds, not hours: raw min/median/max are
600/219,300/10,368,000; converted median is
60.92 hours, maximum 120.0 days. Source units remain
unconfirmed; modelling uses log-transformed hours.

Multi-value unknowns stay distinct from explicit "No red flags"/"No known conditions".
Fixed vocabularies produce multi-hot items, counts and unknown/none indicators.
Severity and pain are ordinal; vitals retain missingness indicators. Imputation,
scaling and learned encodings occur inside fitted pipelines. Prior-request counts
use strictly earlier intake history, including unlabelled requests.

Real issues include missing vitals/text, repeat patients, duplicated blood-pressure
availability signals, limited age coverage and complete grouped-outcome separation
for a red flag. The preparation found 0 newly invalid vital values,
0 duplicate labelled request IDs and 0 negative ages;
passing these checks does not prove measurement accuracy. Full details and thresholds
are in the report and [schema](artifacts/feature_schema.json).

## Findings and methodology

EDA shows higher recorded urgency with severity/pain, red flags, faster heart rate
and lower oxygen saturation. Age differences are modest; recorded sex has similar
urgency composition. Shorter symptom duration accompanies higher urgency in this
cohort. These are descriptive associations, not causal or clinical validation.
Browse [interactive EDA](artifacts/eda/index.html) with its local Plotly bundle.

At artifact alpha **0.05**, **8 of 9 primary
comparisons** are significant after Holm correction in the one-request-per-patient
sensitivity sample. Recorded sex is not significant; age/comorbidity effects are
smaller than severity/red-flag associations. The report includes test statistics,
p-values, effect sizes, assumption failures and post-hoc results. Full-request tests
remain nominal because patients repeat.

Patient-disjoint, chronological splits purge later-window requests from earlier
patients. Model selection used validation only; grouped forward CV, fold-local
preprocessing/resampling, tuning, calibration and decision-rule experiments used
training data. The final configuration was frozen before refitting train plus
validation. Earlier full-cohort EDA/hypothesis analysis limits holdout blinding.

The latest experiment session logs **103 rows**, including
**25 default model/imbalance combinations**. The selected configuration
is **`default_LightGBM_class_weights`**, balancing High/Critical recall, triage errors, macro F1,
calibration and stability. It retains uncalibrated probabilities and argmax decisions.
The cost-sensitive logistic alternative lowers under-triage while increasing
over-triage and reducing macro F1. Tuning did not automatically improve validation
results. See [comparison](artifacts/model_comparison.csv) and the report's tables.

## Final evaluation and explanations

Model `triage-lightgbm-v1-01dd07c4b659` was refit on **11,545 train-plus-validation requests** and
scored on **1,074 test requests**. The ledger records **1
model prediction pass** and **1 evaluation**. The dashboard reads
these saved results without reevaluation.

| Saved test measure | Result |
| --- | --- |
| Accuracy / balanced accuracy | 69.9% / 70.6% |
| Macro / weighted F1 | 0.700 / 0.697 |
| High / Critical recall | 68.4% / 74.4% |
| Under-triage | 166 (15.5%) |
| Over-triage | 157 (14.6%) |
| Severe under-triage | 9 (0.8%) |
| Multiclass Brier / log loss | 0.418 / 0.698 |

Under-triage predicts a lower ordinal rank; over-triage predicts a higher rank.
Severe means Critical→Low/Moderate or High→Low. The dashboard separately highlights
Critical→any lower and High→Low/Moderate, a broader review group containing
68 saved errors. See [metrics](artifacts/model_metrics.json),
[class report](artifacts/classification_report.csv),
[confusion matrix](artifacts/confusion_matrix.png) and
[error table](artifacts/under_over_triage.csv).

Grouped global/per-class SHAP and individual development examples highlight severity,
heart rate, red flags, oxygen saturation and pain. They explain raw class margins,
not causal effects or probability changes. Label-construction circularity remains a
concern. See [explainability notes](artifacts/explainability/explainability_notes.md).

## Safety and limitations

Treat synthetic or limited case-study data as inadequate evidence for clinical use;
the supplied source artifacts do not independently certify data provenance.
Assessments use **5 recorded protocols**, creating potential label noise
and protocol inconsistency that have not been measured through adjudication.
Repeat patients, missingness, inferred duration units, restricted demographics,
unlabelled-request exclusion, repeated validation reuse and earlier whole-cohort
exploration constrain conclusions. There is no external or prospective clinical
validation, fairness assurance, outcome benefit or approved clinical deployment.

Keep qualified human oversight and independent red-flag escalation. A lower predicted
urgency must not cancel a warning sign or delay assessment. Before any future live
use, require clinician-led validation, agreement review, subgroup evaluation,
calibration and drift checks, privacy/access controls and approved escalation
procedures. Production APIs, deployment, live queue integration and autonomous
clinical decisions are outside the case-study scope.

## Reproduction and artifact map

Logic lives in `src/`; notebooks call it. The data-preparation, EDA, hypothesis,
baseline and experimentation notebooks document the development sequence. In a
fresh experiment workspace with the source CSVs, their modules are
`src.data_preprocessing`, `src.eda`, `src.hypothesis_testing`, `src.train`, and
`src.train --experiments`. Finalization uses `src.finalize_model prepare`,
`src.validate_artifacts`, `src.explainability`, then
`src.finalize_model evaluate-test`.

Preserve the existing frozen release. Rebuilding preparation or experiments can
overwrite artifacts: use a separate workspace for a new run. An existing final
ledger prevents refitting and reevaluation; export recovery uses cached probabilities.
Do not delete the ledger to obtain another test score. Earlier analysis artifacts
retain their historical cohort scope; rerunning modules after splits exist may use
a different analysis cohort, which requires regenerating reports.
